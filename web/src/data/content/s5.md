# LIKE, GLOB and collations

## LIKE folds ASCII case

PostgreSQL's `LIKE` is case-sensitive and `ILIKE` is not. SQLite's `LIKE` is already case-insensitive for ASCII. PostgreSQL's `LIKE` is not; it uses `ILIKE` for the other version. `'Ada' LIKE 'a%'` is true here and false in PostgreSQL.

```sql
SELECT 'Ada' LIKE 'a%' AS like_lowercase,
       'Ada' GLOB 'a*' AS glob_lowercase,
       'Ada' LIKE 'A%' AS like_uppercase;
```

| like_lowercase | glob_lowercase | like_uppercase |
| --- | --- | --- |
| 1 | 0 | 1 |

The fold is ASCII only. `'é' LIKE 'É'` is false, and `'İ'` is a different character from `'i'`. If case matters outside ASCII, normalise the value in the application or store a folded copy.

## GLOB is the Unix pattern

`GLOB` is case-sensitive. Its syntax comes from globbing: `*` matches any run of characters, `?` matches one, and `[a-z]` matches a character class. There is no escape character. To match a literal `*`, put it in a bracket expression such as `[*]`.

| | LIKE | GLOB |
| --- | --- | --- |
| Case | folds ASCII | exact |
| Wildcards | `%`, `_` | `*`, `?`, `[...]` |
| Escape | `ESCAPE` | `[*]` class |

```sql
SELECT (SELECT COUNT(*) FROM products WHERE name LIKE '%AN%') AS like_an,
       (SELECT COUNT(*) FROM products WHERE name GLOB '*AN*') AS glob_an;
```

| like_an | glob_an |
| --- | --- |
| 5 | 0 |

Five names contain the letters `an` in some case. None spell them `AN`. The two queries answer different questions; only one of them is the question you asked.

`PRAGMA case_sensitive_like` changes `LIKE` to PostgreSQL's behavior for the connection. It also changes which indexes can serve the query. Treat it as a compatibility switch, not a design choice.

## Collations decide order and equality

A text column has a collation that decides `ORDER BY`, `=`, and `BETWEEN`. The default is BINARY, which compares UTF-8 bytes and puts uppercase before lowercase. SQLite also ships `NOCASE`, which folds ASCII, and `RTRIM`, which ignores trailing spaces.

```sql
SELECT name FROM customers ORDER BY name COLLATE NOCASE;
```

That sort interleaves uppercase and lowercase names the way a person expects. `COLLATE NOCASE` is ASCII only. If you need the sort indexed, bake the collation into the index:

```sql
CREATE INDEX customers_name_nocase ON customers (name COLLATE NOCASE);
```

PostgreSQL chooses a collation from the operating system or ICU, per database or per expression. Different mechanism, same idea.
