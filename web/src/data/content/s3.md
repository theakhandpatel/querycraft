# rowid, INTEGER PRIMARY KEY and AUTOINCREMENT

## Every row has an address

An ordinary SQLite table is a B-tree keyed by a 64-bit signed integer. That integer is the `rowid`. You can read it by three names: `rowid`, `_rowid_`, and `oid`.

```sql
SELECT rowid AS rid, id, name
FROM products
ORDER BY id
LIMIT 3;
```

| rid | id | name |
| --- | --- | --- |
| 1 | 1 | Aurora Wireless Earbuds |
| 2 | 2 | Nimbus Headphones |
| 3 | 3 | Linen Duvet Cover |

The two columns agree because `id INTEGER PRIMARY KEY` makes `id` an alias for the rowid. It is the same value read two ways, not a copy.

## The alias is the key

When a column's declared type is exactly `INTEGER` and it is the table's single `PRIMARY KEY`, SQLite makes that column the rowid. There is no second index and no extra storage. Reading it reads the B-tree key. Inserting into it sets the key.

```sql
SELECT MAX(id) AS max_id, MAX(rowid) AS max_rowid, COUNT(*) AS rows
FROM products;
```

| max_id | max_rowid | rows |
| --- | --- | --- |
| 20 | 20 | 20 |

Three numbers that agree. Twenty products, ids 1 through 20, no gaps, because the id is the key.

`WITHOUT ROWID` reverses the default. The declared `PRIMARY KEY` becomes the storage key, and there is no hidden integer address. Use it for small, narrow tables where the extra lookup costs more than it saves. You cannot select a rowid from such a table.

## AUTOINCREMENT is a promise

Plain `INTEGER PRIMARY KEY` assigns an id when you omit one, but it reuses values. Delete the row with the largest id and the next insert can take that id back, because SQLite picks one more than the current maximum key.

`AUTOINCREMENT` promises never to reuse an id. It stores the highest value ever issued in `sqlite_sequence`, writes that table on each insert, and stops when the id space runs out. If you are porting a schema that depends on monotonic, never-reused keys, this is the SQLite spelling.

| Declaration | Assigns ids | Reuses after delete | Extra storage |
| --- | --- | --- | --- |
| `INTEGER PRIMARY KEY` | yes | yes | none |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | yes | no | `sqlite_sequence` row |

The dataset uses neither keyword. The seed supplies explicit ids, which is fine for a lesson database that gets reset.

## PostgreSQL uses a sequence

PostgreSQL has no rowid. A surrogate key is a column with a default drawn from a sequence: `GENERATED ALWAYS AS IDENTITY` in modern schemas, `serial` in older ones. The sequence is a separate object with its own state, and `nextval` fills the column. That is a different mental model. Only SQLite lets you write `WHERE rowid = 5`.
