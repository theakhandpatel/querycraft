# Dates are not a type

## Store the calendar as text

SQLite has no `DATE` or `TIMESTAMP` type. The words are legal in `CREATE TABLE`, but they are not types. A date string gets NUMERIC affinity, does not look numeric, and lands in TEXT.

The dataset proves it:

```sql
SELECT id, signup_date, typeof(signup_date) AS stored
FROM customers
ORDER BY id
LIMIT 3;
```

| id | signup_date | stored |
| --- | --- | --- |
| 1 | 2025-11-02 | text |
| 2 | 2025-11-15 | text |
| 3 | 2025-12-01 | text |

That is the design. ISO-8601 text sorts lexicographically the way it sorts chronologically, so range filters and `ORDER BY` work without a date type.

## The functions are the calendar

SQLite does date work with functions, not operators.

| Function | Returns |
| --- | --- |
| `date(x)` | `YYYY-MM-DD` |
| `time(x)` | `HH:MM:SS` |
| `datetime(x)` | `YYYY-MM-DD HH:MM:SS` |
| `strftime(format, x)` | the formatted string |
| `julianday(x)` | a Julian day number |
| `unixepoch(x)` | seconds since 1970 |

Grouping by month is the pattern to learn. PostgreSQL uses `DATE_TRUNC('month', ordered_at)::date`; SQLite writes the first of the month with a format string:

```sql
SELECT strftime('%Y-%m-01', ordered_at) AS month, COUNT(*) AS orders
FROM orders
GROUP BY month
ORDER BY month;
```

| month | orders |
| --- | --- |
| 2026-01-01 | 16 |
| 2026-02-01 | 19 |
| 2026-03-01 | 18 |
| 2026-04-01 | 18 |
| 2026-05-01 | 9 |

`strftime` returns NULL for a string it cannot read. A bad date does not raise; it disappears from the group. Pin the format at the boundary where data enters.

## Arithmetic is a modifier string

SQLite has no `INTERVAL`. `date()`, `time()`, and `datetime()` take modifiers: `'+1 month'`, `'-7 days'`, `'+2 hours'`, `'start of month'`. They apply left to right.

```sql
SELECT date('2026-01-31', '+1 month') AS plus_month,
       julianday('2026-02-01') - julianday('2026-01-01') AS days;
```

| plus_month | days |
| --- | --- |
| 2026-03-03 | 31.0 |

`'+1 month'` on January 31 does not clamp to February 28. It normalises to March 3, because the modifier is text arithmetic, not a calendar-aware interval type. Subtracting two Julian day numbers gives a span in days.

A seed date plus `'+1 month'` inside `WITH RECURSIVE` is the SQLite replacement for `generate_series`. The porting course builds that series. Here, know that the modifier is where date arithmetic lives.
