# A database in a file

## One file, one database

A SQLite database is a file. You open it with a path, and the engine runs inside your program. The file and the program share a lifetime.

PostgreSQL is a server. It listens on a port, clients connect with an account, and the data lives in a directory the server owns. SQLite removes that layer. The file is the database.

That changes how you connect. `SELECT COUNT(*) FROM customers;` names a table, not a database. The host opened `commerce.db`; the SQL does not name it.

| | SQLite | PostgreSQL |
| --- | --- | --- |
| Database | one file | a server |
| Engine | in your process | in the server process |
| Connect | open a path | host, port, user, password |

## The catalog is a table

`sqlite_master` (also spelled `sqlite_schema`) has one row per table, index, view, and trigger. The `sql` column stores the `CREATE` statement exactly.

```sql
SELECT type, name
FROM sqlite_master
WHERE type = 'table'
ORDER BY name;
```

| type | name |
| --- | --- |
| table | customers |
| table | dataset_meta |
| table | order_items |
| table | orders |
| table | products |

Because it is a table, you filter it with `WHERE`, `LIKE`, and `ORDER BY` like any other table. `PRAGMA table_info('products')` returns rows the same way.

The lesson dataset also has five indexes. One of them, `sqlite_autoindex_dataset_meta_1`, was created by SQLite from the `dataset_meta` primary key, not by the seed.

## A sandbox you can open read-only

The lesson copy is a file opened read-only. An insert fails:

```sql
INSERT INTO dataset_meta (dataset, version) VALUES ('oops', 1);
```

```
attempt to write a readonly database
```

That is the file refusing the write, not a privilege check. SQLite has no roles. If a process can open the file writable, it can write the data. Chapter 7 covers the consequences.

## One namespace

A file holds one database and one namespace. `ATTACH` adds a second file to the connection, but that is another database, not a schema inside this one. There is no `search_path`; an unqualified name has one place to resolve.

## Check yourself

**1. Why is there no `search_path` in SQLite?**

<details>
<summary>Answer</summary>

Because a file holds one database in one namespace. `search_path` resolves which schema in which database an unqualified name means. With one namespace, there is nothing to resolve.

</details>

**2. Where does the list of tables live, and how do you read it?**

<details>
<summary>Answer</summary>

In `sqlite_master`, one row per schema object. You read it with an ordinary `SELECT`, filtering on `type` and `name` like any other table.

</details>

**3. A write to the lesson dataset fails. Is that a permissions check?**

<details>
<summary>Answer</summary>

No. There are no roles to check. The database file was opened read-only, so the engine refuses the write at the storage layer: `attempt to write a readonly database`.

</details>
