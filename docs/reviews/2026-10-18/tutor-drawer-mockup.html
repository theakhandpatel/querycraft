Section 5

Reading a table

A SELECT names the columns you want back, FROM names the table they come from, and ORDER BY sorts the rows before you read them. Run a query, then read the grid under it: the columns come back in the order you named them.

A WHERE clause keeps only the rows that match. How a match works depends on the column's type, and products.category holds text.

Why is my result wrong? I ran it and got nothing back.
Tutor

Your query is not broken. It matched no rows. PostgreSQL compares text with = case-sensitively, and category stores 'Electronics' with a capital E. The string 'electronics' is a different value, so the WHERE clause keeps nothing.

Read the stored values for yourself:

SELECT DISTINCT category
FROM products;

Those five rows are what your clause has to match. Once the value matches, the ORDER BY price you already wrote sorts cheapest first.
