The result is the answer.

An exercise declares the columns, the row order, and the values that count as correct. Any query that produces them passes: a join, a subquery, a window function. A query that returns the wrong rows fails, however tidy it looks.

What the contract checks

Columns and order

The result has the expected columns, in the expected order.

Rows

The right rows, with no extras and none missing.

Row order

When the exercise asks for an order, the rows arrive in it.

Values

Each value matches, with the comparison the exercise declares.

The app never compares your SQL text. Two different queries can both be right.

PostgreSQL first. SQLite too.

PostgreSQL is the main engine. Three SQLite courses teach where the two diverge: types, dates, the rowid, and the queries that have no direct port. The same grading rules apply to both.

PostgreSQL
select date_trunc('month', ordered_at) as month,
       count(*) as orders
from orders
group by 1
order by 1;
SQLite
select strftime('%Y-%m', ordered_at) as month,
       count(*) as orders
from orders
group by 1
order by 1;
